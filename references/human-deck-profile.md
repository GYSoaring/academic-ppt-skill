## 结论一：正文字号是 16 pt，不是 20

五份里四份正文都落在 16 pt（有一份 17 pt）。在 13.33 in 宽的版面上 16 pt 完全可读——因为**它们的字少**（197 字/页）。字号大不是专业感，克制才是。

本机的 `lecture` 阶梯正文是 44 px ≈ 20.6 pt，偏大一档。可以接受（投影更保险），但**不能再往上加**。

## 结论二：标题不该那么大

标题字号 / 版面宽的中位数是 **1.8**，加权 1.98。原来的 `lecture` 是 68 px ≈ 31.9 pt → **2.39**，比真人高出 20–30%。

已改成 58 px ≈ 26.7 pt → **2.04 pt/in**，落进真人的区间。封面标题例外，仍可放大。

## 结论三：元素少，是因为不用容器

真人 15 个元素/页里只有 8.9 个是文本框，剩下约 6 个是装饰（含背景、页码、分隔线）。我们的 deck 28 个元素里 13.5 个是文本框，**多出来的全是容器**：每个面板 ≈ 2.5 个形状（卡片 + 标题条 + 图标），每个流程节点 ≈ 2.5 个。

这不是"风格差异"，是**每个内容块都被包了一层**。真人的做法是文字直接落在版面上，靠留白和对齐分组，不靠边框。

> 目标：**每页 ≤ 15 个元素、≤ 9 个文本框**。当前 28.2 / 13.5 —— 差距全在容器上。

## 结论四：文本框占版面 0.25

真人 0.25，我们 0.386。文本块占版面超过三分之一，页看起来就"满"。修法不是缩字号，是**收窄文本块的宽度**，把右侧留成气口。

## 结论五：字号档要 11–13 级

真人 13 级，我们 10 级。档位多说明层级细：kick 小字、图注、页码、标签各有一级。层级少会逼着不同用途的文本挤在同一档。

## 结论六：字体选择

- 微软雅黑 3/5（最主流）
- Times New Roman 2/5（西文与数字）
- 华文中宋、方正苏新诗柳楷简体各 1 份

**方正苏新诗柳楷简体**出现在"天津大学+赵智博"那份里——说明真人确实会用**书法体写单位名**，而不是全篇一个黑体。这印证了 `fonts.brand` 的必要性。

## 怎么用这份画像

```bash
# 量一份新参考
python scripts/analyze_reference.py 某个deck.pptx --out profile.json

# 量一批，出汇总
python scripts/analyze_reference.py a.pptx b.pptx c.pptx --aggregate --out profile.md

# 量自己生成的（同一把尺子，才能比）
python scripts/analyze_reference.py out/xxx.pptx --out mine.json
```

比对时看五个数：元素/页、文本框/页、文本占版面比、标题 pt/in、字/页。其余是次要的。
